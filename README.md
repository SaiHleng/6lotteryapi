# TRX Virtual Fixed-Bet Telegram Bot

**Virtual-only simulator** for fixed-stake BIG / SMALL style rounds.

> ⚠️ **This project has no live betting capability.**  
> It is **not** connected to 6Lottery (or any other operator).  
> No real money is moved. Outcomes are generated by a fair 50/50 random choice.  
> The 1.90× gross payout is a **hypothetical** test value only.

Use it to:
- practise risk limits (stop-loss / take-profit / max daily bets)
- experiment with Telegram bot UX
- develop and test a virtual ledger before any authorised live integration

---

## Features

- Owner-only Telegram control panel
- SQLite virtual ledger with daily P/L tracking
- Configurable fixed stake, side, interval and risk limits
- Automatic session pause on risk limits or process restart
- Clean separation between virtual engine and future live API contract
- Unit tests for the core simulation logic

## Quick Start

### Requirements

- Python 3.10+
- A Telegram bot token from [@BotFather](https://t.me/BotFather)

### Installation

```bash
git clone https://github.com/YOUR_USERNAME/trx_virtual_telegram_bot.git
cd trx_virtual_telegram_bot

python -m venv .venv
# Linux / macOS
source .venv/bin/activate
# Windows PowerShell
# .venv\Scripts\Activate.ps1

pip install -r requirements.txt
cp .env.example .env
```

Edit `.env`:

```env
TELEGRAM_BOT_TOKEN=123456:ABC-DEF...
ALLOWED_CHAT_ID=          # leave empty for the first run
```

### First run

```bash
python bot.py
```

1. In Telegram, open a chat with your bot and send `/id`.
2. Copy the chat ID into `.env` as `ALLOWED_CHAT_ID=...`.
3. Restart the bot.
4. Use `/start`, `/stake 100`, `/side big`, `/limits 3000 3000 40`, `/run`.

## Commands

| Command              | Description                                      |
|----------------------|--------------------------------------------------|
| `/id`                | Show your Telegram chat ID                       |
| `/start` / `/help`   | Help text                                        |
| `/status`            | Balance, daily P/L, current settings             |
| `/stake 100`         | Fixed stake (100 – 10 000 virtual units)         |
| `/side big\|small`   | Fixed side                                       |
| `/interval 60`       | Seconds between virtual rounds (15 – 3600)       |
| `/limits 3000 3000 40` | Daily stop-loss, take-profit, max bets         |
| `/run`               | Start auto simulation                            |
| `/stop`              | Pause simulation                                 |
| `/history`           | Last 8 simulated rounds                          |
| `/reset CONFIRM`     | Wipe ledger and reset balance to 100 000         |

## Future authorised live integration

See `authorized_api_template.py`.

Any live client **must**:

1. Use only endpoints and credentials provided by the operator.
2. Carry a unique idempotency key on every money-moving request.
3. Never auto-retry after a timeout — always reconcile first.
4. Read settlement exclusively from the official source of truth.
5. Keep virtual mode and live mode in completely separate code paths.

This repository deliberately contains **no** live implementation.
